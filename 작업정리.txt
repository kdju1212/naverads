[실계정 수정 — 모두 실제 호출로 성공 확인]
- ON/OFF: 캠페인, 광고그룹, 키워드, 소재, 확장소재
- 키워드 입찰가, 광고그룹 기본 입찰가, 캠페인 일예산
- 수정 후 네이버 응답에 값이 반영됐는지 비교 → 안 됐으면 "반영되지 않았습니다"로 실패 처리

[확장소재 생성·삭제 — 실계정 확인 완료 (10/19)]

  ※ 앱에서 "추가설명"이라고 부르던 DESCRIPTION은 실제로 네이버의 "홍보문구"였음 → 이름 수정

  (이미지 서브링크·파워링크 이미지 등은 네이버 API로 생성 불가)
- ON/OFF, 삭제 성공. 네이버에 이미 없으면 앱 목록에서만 정리하고 이력에 "네이버에 이미 없음"
- 내용 수정: 네이버 API가 지원하지 않음(수정 가능 필드는 userLock, period뿐) → 새로 만들고 기존 것 삭제

  ※ 10/19에 만든 확장소재는 하루 뒤(10/20) 네이버 목록에 그대로 있음 확인

[키워드 자동입찰 (10/19 배포)]
- 자동입찰 메뉴에서 키워드 선택 → 기기(PC/모바일), 목표 순위(PC 1~10위, 모바일 1~5위), 최대 입찰가 → "자동입찰 설정"
- (10/23부터 검색 화면 순위 방식 — 아래 "자동입찰 크롤링 전환" 참고. 예전엔 공식 API "순위별 예상 입찰가"로 맞춤)
- 10분마다 자동 실행(Cloudflare 크론, 10/23 전엔 매시 정각) + "지금 실행" 버튼, "해제"
- 변경은 대량 작업(출처 "자동입찰")으로 실행 → 권한 확인·네이버 반영 검증·이력 기록 동일
- 입찰가가 같으면 변경 안 함. 자동입찰 표 "최근 실행" 칸에 마지막 결과 표시
- 실행은 규칙을 저장한 사람의 권한으로 함 (권한이 없어지면 그 규칙은 실행 안 됨)
- 개수 제한 (10/20): 조직당 켜진 자동입찰 20개까지 (무료 플랜 호출 한도 때문). 넘으면 저장 시 오류 안내
  중지된 규칙은 세지 않음. 유료 플랜 전환하면 backend/src/app/main.py AUTO_BID_LIMIT 값을 올리면 됨
  ※ 실계정 "지금 실행" 결과는 아직 확인 전 — 지금 계정은 파워링크를 실제로 돌리지 않아 확인 보류
    (파워링크를 운영하는 계정이 생기면 키워드 1개, 낮은 최대 입찰가로 먼저 확인)

[자동입찰 크롤링 전환 + 지금 순위 (10/23)]
- 네이버 공식 API에는 "지금 몇 위" 조회가 없음 (/stats avgRnk는 기간 평균). 다른 자동입찰 솔루션도 검색 화면을 읽는 것으로 보임
- 읽는 화면: PC https://ad.search.naver.com/search.naver?where=ad&query=키워드
            모바일 https://m.ad.search.naver.com/search.naver?where=m_expd&query=키워드  (파워링크 전체 목록, PC 25개·모바일 15개)
  HTML 안 소재 ID(nad-a001-01-…)가 노출 순서대로 있음 → 키워드의 광고그룹 소재 ID가 처음 나오는 위치 = 순위 (주소 비교 안 함)
  10/23 Cloudflare(wrangler dev --remote, LAX)에서도 country KR로 같은 목록 받는 것 확인
- 코드: backend/src/app/naver.py serp_ads, bulk.py _rank·next_bid·check_ranks·run_auto_bids
- 조정 규칙(next_bid): 목표보다 아래·노출 안 됨 → +20%, 위 → -10%, 같으면 그대로. 최소 10원씩, 70원~최대 입찰가
  그룹 입찰가를 쓰는 키워드는 그룹 입찰가를 현재값으로 봄
- 안전장치: 키워드·광고그룹 OFF면 건너뜀(캠페인 OFF는 안 봄), 화면에서 광고를 하나도 못 읽으면(차단·화면 변경) 실패로 보고 안 바꿈
- 최근 실행 칸 예: "지금 5위 (목표 1위) · 300원 → 360원", "지금 3위 (목표 3위) · 변경 없음", "· 변경 없음 (최대 입찰가)"
- "지금 순위" 버튼: 키워드·자동입찰 화면, 선택한 키워드 10개까지 PC·모바일 순위 (POST /workspaces/{id}/ranks, 보기 권한)
- 크론 */10 * * * * (backend/wrangler.jsonc)
- 위험: 네이버 약관상 자동 수집 금지 소지, 많이 읽으면 차단될 수 있음, 화면 구조 바뀌면 serp_ads 수정 필요
  지역·사용자마다 순서가 다를 수 있어 "서버에서 본 순위"
- 백엔드 테스트 14개 통과

  (연결된 자동입찰 규칙·성과 통계도 함께 삭제, 조회 중 오류가 나면 아무것도 지우지 않음)
- 배포 후 실계정 동기화 성공, 남아 있어야 할 항목은 모두 그대로 불러옴 (확장소재 6개 유형 10개)
  ※ 네이버에서 지운 항목이 앱에서도 사라지는지는 아직 확인 전 (지울 일이 생기면 확인)

- 일별 추이: 광고비·클릭수·전환수 그래프(마우스 올리면 그날 값), "표로 보기"로 날짜별 표
- 운영 현황: 연결 계정 수, 캠페인·광고그룹·키워드 ON/OFF, 소재·확장소재 검수 중·반려, 자동입찰 키워드 수
- 광고주별 성과 표에 노출·CTR·CPC 추가. 상단 계정 선택·파워링크/쇼핑 필터 반영
- 실계정에서 화면 확인 완료 (지금은 성과 기록이 없어 0 — 노출이 생기면 그래프·증감 확인)
  ※ 배포 직후 "Not Found"가 잠깐 뜨면 새로고침 (프론트가 백엔드보다 먼저 배포된 경우)

[키워드 대량 등록·삭제 (10/20) — 실계정 등록·삭제 확인 완료]
- 키워드 등록 메뉴 (10/22에 키워드 화면에서 분리)
  1) 광고그룹 ID 입력(붙여넣기 또는 목록에서 선택) → 아래에 "광고주 · 캠페인 > 광고그룹" 표시로 확인
     (캠페인마다 같은 이름의 광고그룹이 있어 이름 대신 ID로 지정)
  2) 키워드를 한 줄에 하나씩. 입찰가 칸에 넣으면 전체 적용, 줄마다 "키워드|입찰가"로 쓰면 그 줄이 우선
     둘 다 비우면 70원 (10/20 사용자 요청. 이전엔 광고그룹 입찰가였음) ※ 70원 등록은 실계정 확인 전
  3) "N개 등록 미리보기" → 작업 화면에서 실행
- 키워드 선택 → "삭제" 버튼 → 미리보기 → 실행. 삭제하면 그 키워드의 자동입찰 규칙도 같이 삭제
- ON/OFF·입찰가 대량 변경은 기존 기능 그대로
- 엑셀(엑셀 대량 작업 화면): 등록 keyword · 광고그룹 ID · create · 키워드|입찰가 / 삭제 keyword · 키워드 ID · delete · 빈칸
- 미리보기에서 걸러내는 것: 같은 키워드 중복, 이미 있는 키워드, 쇼핑 광고그룹, 입찰가 형식(70~100,000원, 10원 단위)
- 네이버 API에서 알게 된 것 (실계정)
  · 등록 POST /ncc/keywords?nccAdgroupId= — 그룹 입찰가를 써도 bidAmt가 없으면 3916 "No value is entered in the default bid..."
  · 항목별 실패는 HTTP 200 + resultStatus(code, message)로 옴 → 실패 사유에 네이버 메시지 그대로 표시
  · 삭제는 DELETE /ncc/keywords/{id} 경로 방식만 됨. 공식 샘플의 ?ids= 방식은 1018 "No permission" (확장소재와 반대)
    코드는 경로 방식 → 실패 시 ids 방식 순서로 시도, 둘 다 실패하면 두 오류를 모두 사유에 남김
  · 기존 키워드(자하라밤/zaharabalm)도 삭제 확인

[연관 키워드 (10/20) — 실계정 확인 완료]
- 키워드 등록 칸에서 검색어(쉼표로 최대 5개, 띄어쓰기 자동 제거) → 네이버 키워드 도구(/keywordstool)
  연관 키워드 · PC/모바일 월 검색량(최근 30일, 10 미만은 "10 미만") · 경쟁 정도. 검색량 많은 순 상위 100개
- 체크(전체 선택/해제 가능) → "선택한 N개 아래 목록에 추가" → 등록
- 선택한 광고그룹의 광고주 계정 API 키로 조회 (추가 비용 없음)
- "탈취제"는 많이 나옴. "자하라밤"처럼 검색이 적은 브랜드명은 자기 자신만 나옴(네이버 데이터 부족) → 상품 종류를 같이 넣기
- 네이버가 더 주지만 아직 안 보여 주는 값: 월 평균 클릭수·클릭률·평균 노출 광고 수

[광고그룹 화면 (10/20)]
- "다운로드 (엑셀)": 광고주·유형(파워링크/쇼핑검색)·캠페인명·캠페인 ID·광고그룹명·광고그룹 ID·상태·운영 상태·하루예산
  CSV(엑셀에서 열림), 상단 계정·유형 필터 적용 → 키워드 등록할 광고그룹 ID 찾는 용도
- 표에 운영 상태·하루예산 칸 추가
- 하루예산: 동기화 때 네이버 dailyBudget 저장(useDailyBudget=false면 "제한 없음") ※ 공유예산 그룹은 아직 반영 안 함
- 운영 상태: 네이버 statusReason(없으면 status)을 한글로 — 캠페인/광고그룹 예산 소진, 캠페인 OFF, 캠페인 시작 전·종료,
  비즈채널 검수 중·반려·중지, 일부 제한, 노출 가능. 광고그룹이 OFF면 "광고그룹 OFF"(+ 다른 이유가 있으면 " · 이유")
  "노출 가능"이 아니면 주황색. 마지막 동기화 시점 기준(실시간 아님)
  실계정 확인: "광고그룹 OFF" 표시 확인. 예산 소진 등 다른 이유는 그런 상황이 생기면 확인

[대량 작업 나눠 실행 (10/20)]
- 실행 요청 1번에 3행씩(EXECUTE_CHUNK) 처리, 화면이 끝날 때까지 자동으로 이어서 요청
- 중간에 끊긴 "실행 중" 작업은 작업 화면의 "남은 N건 이어서 실행"으로 재개
- 이유: 무료 플랜은 요청당 D1 쿼리+외부 호출 50번까지 (로컬 측정: 실행 5행 = 쿼리 32 + 네이버 5, 20행 = 쿼리 92 + 네이버 20)
  ※ 작업 #18이 멈췄던 실제 원인은 한도가 아니라 위의 3916이었음(응답에 키워드 ID가 없어 서버 오류)

[디버깅 방법 (10/20에 사용)]
