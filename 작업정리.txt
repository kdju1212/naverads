- 확인 방법: GitHub 커밋의 "Workers Builds: naverads", "Workers Builds: naverads-api" 둘 다 성공 후 테스트
  (프론트가 먼저 배포되면 잠깐 "Not Found", "알 수 없는 유형" 같은 오류가 날 수 있음)
- 백엔드 Secret APP_SECRET 설정 확인됨 (네이버 비밀키 암호화 저장에 사용)
- DB 스키마 변경은 자동 배포되지 않음 → push 전에 직접 실행 (backend 폴더에서)
  npx wrangler d1 migrations apply naverads --remote
  (0003_auto_bid_rules 적용 완료, 0004_adgroup_daily_budget 적용 완료 10/20, 0005_adgroup_serving 적용 완료 10/20)

[계정 연결]
- 네이버 검색광고 API 키 등록 + 실계정(CUSTOMER_ID) 연결·동기화 성공
- 설정 화면 표기 "고객 ID" → "CUSTOMER_ID"

[조회 (동기화)]
- 캠페인, 광고그룹, 키워드, 소재
- 반응형 검색광고(RSA_AD) 소재: 파워링크 탭에 표시, 제목·설명(assets)까지 저장
- 확장소재: 파워링크 캠페인·광고그룹의 확장소재 동기화 + 확장소재 화면
- 성과 통계: 캠페인별 일별 30일(어제까지) — 노출·클릭·비용(VAT 포함)·전환
  ※ 현재 값이 모두 0. 소재가 검수 중이라 노출이 없어서인지 네이버 화면과 비교 필요

[실계정 수정 — 모두 실제 호출로 성공 확인]
- ON/OFF: 캠페인, 광고그룹, 키워드, 소재, 확장소재
- 키워드 입찰가, 광고그룹 기본 입찰가, 캠페인 일예산
- 수정 후 네이버 응답에 값이 반영됐는지 비교 → 안 됐으면 "반영되지 않았습니다"로 실패 처리

[확장소재 생성·삭제 — 실계정 확인 완료 (10/19)]
- 새로 만들기: 홍보문구(DESCRIPTION), 서브링크(이름 | URL) 실계정 성공 — 매일 24시간 노출, 광고그룹 비즈채널 사용
  ※ 앱에서 "추가설명"이라고 부르던 DESCRIPTION은 실제로 네이버의 "홍보문구"였음 → 이름 수정
- 10/19 추가: 추가제목(HEADLINE, 15자), 추가설명(DESCRIPTION_EXTRA, 45자)
  홍보문구는 구분(할인·사은품·추가선물증정·이벤트·신상품) 선택 + 14자 — 실계정 생성 확인 완료
  (이미지 서브링크·파워링크 이미지 등은 네이버 API로 생성 불가)
- ON/OFF, 삭제 성공. 네이버에 이미 없으면 앱 목록에서만 정리하고 이력에 "네이버에 이미 없음"
- 내용 수정: 네이버 API가 지원하지 않음(수정 가능 필드는 userLock, period뿐) → 새로 만들고 기존 것 삭제
  ※ 10/18에 만든 1건이 20분 뒤 네이버 목록에서 사라진 적 있음 — 사용자가 직접 삭제했을 가능성 있음
  ※ 10/19에 만든 확장소재는 하루 뒤(10/20) 네이버 목록에 그대로 있음 확인

[키워드 자동입찰 (10/19 배포)]
- 키워드 화면에서 키워드 선택 → 기기(PC/모바일), 목표 순위(PC 1~10위, 모바일 1~5위), 최대 입찰가 → "자동입찰 설정"
- 네이버 공식 API(/estimate/average-position-bid)의 "순위별 예상 입찰가"로 입찰가를 맞춤, 최대 입찰가를 넘지 않음
  ※ 실시간 순위가 아니라 과거 평균 순위 통계 기반 예상값 (네이버 공식 API에 실시간 순위 없음)
- 매시 정각 자동 실행(Cloudflare 크론) + "지금 실행" 버튼, "해제"
- 변경은 대량 작업(출처 "자동입찰")으로 실행 → 권한 확인·네이버 반영 검증·이력 기록 동일
- 입찰가가 같으면 변경 안 함. 키워드 표 "자동입찰" 칸에 마지막 결과 표시
- 실행은 규칙을 저장한 사람의 권한으로 함 (권한이 없어지면 그 규칙은 실행 안 됨)
- 개수 제한 (10/20): 조직당 켜진 자동입찰 20개까지 (무료 플랜 호출 한도 때문). 넘으면 저장 시 오류 안내
  중지된 규칙은 세지 않음. 유료 플랜 전환하면 backend/src/app/main.py AUTO_BID_LIMIT 값을 올리면 됨
  ※ 실계정 "지금 실행" 결과는 아직 확인 전 — 지금 계정은 파워링크를 실제로 돌리지 않아 확인 보류
    (파워링크를 운영하는 계정이 생기면 키워드 1개, 낮은 최대 입찰가로 먼저 확인)

[동기화 정리 (10/19)]
- 동기화 때 네이버가 돌려주지 않은 캠페인·광고그룹·키워드·소재·확장소재를 앱에서도 삭제
  (연결된 자동입찰 규칙·성과 통계도 함께 삭제, 조회 중 오류가 나면 아무것도 지우지 않음)
- 배포 후 실계정 동기화 성공, 남아 있어야 할 항목은 모두 그대로 불러옴 (확장소재 6개 유형 10개)
  ※ 네이버에서 지운 항목이 앱에서도 사라지는지는 아직 확인 전 (지울 일이 생기면 확인)

[대시보드 (10/19)]
- 요약 카드 8개: 광고비·노출수·클릭수·CTR·CPC·전환수·매출·ROAS + 직전 같은 기간 대비 ▲▼%
- 일별 추이: 광고비·클릭수·전환수 그래프(마우스 올리면 그날 값), "표로 보기"로 날짜별 표
- 운영 현황: 연결 계정 수, 캠페인·광고그룹·키워드 ON/OFF, 소재·확장소재 검수 중·반려, 자동입찰 키워드 수
- 광고주별 성과 표에 노출·CTR·CPC 추가. 상단 계정 선택·파워링크/쇼핑 필터 반영
- 실계정에서 화면 확인 완료 (지금은 성과 기록이 없어 0 — 노출이 생기면 그래프·증감 확인)
  ※ 배포 직후 "Not Found"가 잠깐 뜨면 새로고침 (프론트가 백엔드보다 먼저 배포된 경우)

[키워드 대량 등록·삭제 (10/20)]
- 키워드 화면: "키워드 등록" 칸에서 광고그룹 선택 → 한 줄에 하나씩 "키워드" 또는 "키워드|입찰가" 붙여넣기
  (입찰가 비우면 광고그룹 입찰가). 키워드 선택 → "삭제" 버튼. ON/OFF·입찰가 변경은 기존 그대로
- 엑셀: keyword · 광고그룹 ID · create · 키워드|입찰가 / keyword · 키워드 ID · delete · 빈칸
- 둘 다 대량 작업 미리보기 → 실행 → 이력 (같은 키워드 중복, 이미 있는 키워드, 쇼핑 광고그룹은 미리보기에서 걸러냄)
- 삭제하면 그 키워드의 자동입찰 규칙도 같이 삭제
- 네이버 공식 명세 기준: 등록 POST /ncc/keywords?nccAdgroupId=, 삭제 DELETE /ncc/keywords?ids=
  ※ 실계정 확인 전 — OFF인 광고그룹에 키워드 1개 등록 → 삭제로 먼저 확인
- 광고그룹은 ID로 지정 (캠페인마다 같은 이름의 광고그룹이 있어서). ID 칸에 붙여넣거나 목록에서 고르면
  "광고주 · 캠페인 > 광고그룹"으로 맞는지 보여 줌
- 연관 키워드: 검색어(쉼표로 최대 5개) → 네이버 키워드 도구(/keywordstool)의 연관 키워드·PC/모바일 월 검색량·경쟁 정도
  → 체크해서 등록 목록에 추가. 검색량 많은 순, 상위 100개 표시. 선택한 광고그룹의 광고주 계정으로 조회
  ※ 실계정 확인 전
- 광고그룹 화면 "다운로드 (엑셀)": 광고주·유형(파워링크/쇼핑검색)·캠페인명·캠페인 ID·광고그룹명·광고그룹 ID·상태·운영 상태·하루예산 (CSV, 상단 필터 적용)
  운영 상태 = 네이버 statusReason(없으면 status): 캠페인/광고그룹 예산 소진, 캠페인 OFF, 비즈채널 검수 중 등 (동기화 시점 기준)
  광고그룹 하루예산은 동기화 때 저장(0004 마이그레이션), 네이버에서 하루예산 미사용이면 "제한 없음"
  ※ 공유예산을 쓰는 광고그룹은 아직 반영 안 함

■ 할 것
----------------------------------------------------------------
1. 자동입찰 실계정 확인 (보류: 파워링크 운영 계정 필요) — "지금 실행" 결과(예상 입찰가 API 동작), 매시 정각 자동 실행 확인
2. (완료 10/20) 자동입찰 개수 제한 — 조직당 20개
3. 네이버에서 지운 항목이 동기화 후 앱에서도 사라지는지 확인 (지울 일이 생기면)
   (만든 확장소재 유지 여부는 10/20 확인 완료 — 그대로 있음)
4. 성과 통계 확인 — 노출이 생긴 뒤 네이버 화면 숫자와 비교 (대시보드 그래프·증감도 같이 확인)
5. 엑셀 신규 등록 — 키워드 완료(10/20, 실계정 확인 필요). 남은 것: 소재·확장소재
   - API 등록이라 네이버 대량 관리 양식은 필요 없음 (앱 자체 양식)
   - 나중에: SMB 광고주용 쉬운 등록 화면 (이름으로 고르기, 입찰가 한 번 입력 + 순위별 예상 입찰가 안내, 결과 한 줄 요약)
6. 쇼핑 소재 입찰가 — 쇼핑검색 계정 연결 후
   (명세상 수정 필드에 없고 응답에도 값이 안 와서 실호출로 확인 필요)
7. 동기화 끊김 대비 → 무료 플랜 유지, 지금은 그대로 두기로 함 (10/20). 끊기기 시작하면 그때 대응
   - 무료: 요청당 CPU 10ms, 외부 호출+D1 쿼리 합쳐 50번
   - 지금 D1 연결은 바뀐 행마다 쿼리 1번 → 한 번 동기화에서 40행쯤 바뀌면 끊길 수 있음
     (첫 동기화·입찰가 대량 변경 직후·광고그룹 많은 계정이 위험)
   - 대응 방법: 동기화를 여러 요청으로 나누고 D1 쓰기를 batch로 묶기 (또는 유료 플랜 $5/월 — 사용 안 하기로 함)
