■ 운영 방법
----------------------------------------------------------------
- 배포: main에 push하면 Cloudflare Workers Builds가 프론트(naverads)·백엔드(naverads-api) 자동 배포
  GitHub 커밋의 Workers Builds 두 개가 성공한 뒤 확인 (프론트가 먼저 뜨면 잠깐 "Not Found" → 새로고침)
- DB 변경은 자동 배포 안 됨 → push 전에 backend 폴더에서: npx wrangler d1 migrations apply naverads --remote
  (0011까지 적용 완료)
- 디버깅: npx wrangler tail naverads-api --format json / DB 읽기: npx wrangler d1 execute naverads --remote --command "SELECT ..."
- 무료 플랜만 사용: 요청 1번에 외부 호출+D1 쿼리 50번, CPU 10ms → 대량 작업은 5행씩 나눠 실행, 크론도 조금씩 나눠 진행
- 광고 데이터(캠페인~확장소재)는 서버 DB에 없음: 브라우저(IndexedDB)가 네이버 마스터 보고서로 받아 보관(7일, 화면 "새로고침")
  서버 DB에는 회원·조직·계정 연결·API 키·자동입찰·목표 ROAS·작업 결과·이력·성과 통계만
- 점검 전용 계정: 프로젝트 루트 .test-account (git 제외, 광고 계정 연결 없음)
- 연결된 실계정: 조직 "sdf" — 광고주 김동주 (CUSTOMER_ID 4285993)


■ 기능 (모두 배포됨, ✔ = 실계정 확인)
----------------------------------------------------------------
[조회] 캠페인·광고그룹·키워드·소재(RSA 제목·설명 포함)·확장소재 ✔, 광고그룹 운영 상태·하루예산 ✔,
       성과(대시보드·광고주별·일별, 키워드·광고그룹별 "성과 보기") — 노출이 없어 숫자는 아직 0
[수정] ON/OFF(캠페인~확장소재), 입찰가(키워드·광고그룹), 캠페인 일예산 ✔ — 반영 안 되면 실패 처리
[등록·삭제] 키워드 등록(입찰가 비우면 70원)·삭제 ✔, 소재 등록(MCP)·삭제 ✔, 확장소재 등록·삭제 ✔,
       제외검색어 등록·삭제 ✔·목록 조회 ✔(10/27)
[대량 작업] 화면·엑셀 → 미리보기 → 실행(또는 예약 실행), 작업 결과·실패만 재실행, 변경 이력
[예약 실행] 미리보기 화면에서 시각 지정 → 크론(10분마다)이 실행, 최대 10분 늦음, DB에 저장 ✔(10/27 23:17 예약 → 23:20 크론 실행)
[자동입찰] 키워드별 목표 순위 — 10분마다 검색 화면을 읽어 아래면 +20%, 위면 -10% (최대 입찰가까지, 조직당 20개)
[목표 ROAS] 대시보드에서 광고주 계정별 목표 ROAS·최대 입찰가·무전환 OFF 비용 (10/27)
       매일 9시 이후 파워링크 키워드별 7일 ROAS로 ±10%, 계정 ROAS가 목표 미달이면 내리기만, 크론 1번에 광고그룹 1개씩
[예산 증액] 개발 중 — 다음 달 예산 증액은 자동 실행하지 않고 광고주 승인 후 진행하는 방식으로 설계 예정(지금 코드엔 없음)
[도구] 연관 키워드(검색량 상위 100개) ✔, 키워드 조합기, UTM 빌더, SEO·GEO 점검(스마트스토어 차단), 지금 순위
[MCP] 조회·성과·연관 키워드·자동입찰·작업 기록·미리보기→실행·예약(schedule_job)·소재/확장소재 등록·제외검색어 목록
       ※ 새 도구는 새 대화부터 보임. Claude Code에서 실행(execute_job)이 권한 확인에 막히면 "작업 N 실행해"로 다시 요청


■ 자동화 안전장치 (10/27 보안 점검, 로컬 반영·테스트 25개 통과, 배포 전)
----------------------------------------------------------------
- 예약: 만든 사람·관리자만 예약 가능 / 예약 중엔 직접 실행 막음(두 번 반영 방지) /
        실행 때 지금 값이 미리보기 값과 다르면 그 행은 실패(덮어쓰기 방지, 그룹 입찰가 키워드·예산 미사용은 비교 안 함) /
        예상 못 한 오류면 그 작업을 실패로 끝냄(뒤 작업 막힘 방지)
- 크론: 예약·자동입찰·목표 ROAS를 따로 감싸 하나가 죽어도 나머지는 돎
- 자동입찰: 키워드당 하루 24번까지(AUTO_BID_DAILY_MAX) / "지금 실행"은 부른 사람이 수정 가능한 계정 규칙만
- 목표 ROAS: 계정 7일 전환 0건이면 무전환 OFF 안 함(전환 추적 없음 대비) / 순위 자동입찰 걸린 키워드는 건드리지 않음
- 로그인: 같은 이메일 15분 안 5번·같은 IP 30번 틀리면 15분 막음(웹·MCP 로그인 모두, 없는 이메일도 똑같이). 성공하면 실패 기록 삭제
  단점: 남의 이메일로 일부러 5번 틀리면 그 사람이 15분 못 들어옴
- 토큰 강제 폐기: 설정 > 내 계정에서 비밀번호 변경·모든 기기 로그아웃 → 이전 로그인·Claude 연결 토큰 모두 무효(users.token_version)
  비밀번호 변경은 지금 기기만 새 토큰으로 유지. 버전 없는 예전 토큰은 버전 0으로 인정(배포 때 전원 로그아웃 안 되게)
  한계: 일반 "로그아웃"은 이 기기 토큰만 지움(서버 폐기 아님, 12시간 뒤 만료)
- 원래 있던 것: 실행 직전 권한 재확인, 네이버 반영 검증, 순위 못 읽으면 입찰 변경 안 함, 비밀키 암호화, MCP PKCE·redirect 제한
- 정책 메모: MVP는 ROAS를 분석·추천용으로만 쓰기로 했으나 자동운영이 들어가 있음 → 무전환 OFF 기본 꺼 둠·켤 때 동의 받기 검토


■ 네이버 API에서 알게 된 것 (코드 고칠 때 참고)
----------------------------------------------------------------
- 공식 API에 "지금 몇 위"가 없음 → 검색 화면(ad.search.naver.com, m.ad.search.naver.com) HTML의 소재 ID 순서로 순위 판단
  위험: 약관상 자동 수집 소지, 차단·화면 변경 시 naver.py serp_ads 수정. 10/26부터 서버에서 광고 목록을 못 읽는 중 → 아래 "순위 읽기 문제"
- 키워드 등록: 그룹 입찰가를 써도 bidAmt 필수(3916). 항목별 실패는 HTTP 200 + resultStatus
- 키워드 삭제는 DELETE /ncc/keywords/{id}만 됨(ids 방식은 1018), 확장소재는 반대로 ids 방식만 됨
- 소재 삭제는 본문 없는 204 → Workers httpx 오류 → 본문 없음 = 성공 처리
- 확장소재·소재 문구 수정 불가 → 새로 만들고 기존 것 삭제. 앱의 "홍보문구"가 네이버 DESCRIPTION
- 소재 문구에 가운뎃점(·) 쓰면 1030 오류 → 쉼표
- 마스터 보고서는 계정당 100개 한도 → 받은 뒤 삭제, 한도 오류면 전부 지우고 다시 생성
- 마스터 보고서 파일은 헤더 없는 TSV (칸 구성은 메모리·naverData.ts 참고), 큰 파일은 파이썬 대신 JS fetch로 넘김
- 제외검색어: /ncc/adgroups/{grp}/restricted-keywords (등록 응답 ID rst-…, 삭제는 ?ids=)
