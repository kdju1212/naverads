## 배포 (2026-10-18)
- Cloudflare Python Workers 무료 플랜 + D1: https://naverads-api.djkim0509.workers.dev
- 실제 배포 환경에서 end-to-end 스모크 테스트(가입→계정 연결→동기화→대량 작업→엑셀→성과→대시보드): 3회 중 2회 통과.
- **무료 플랜 CPU 한도가 가장 큰 위험.** 측정 CPU: 조회·대량 작업·대시보드 4~90ms, 로그인 30~70ms, 가입 400~700ms, 계정 동기화(Mock 16개 객체+30일 성과) 350~650ms. 동기화 같은 무거운 요청이 연달아 오면 다음 요청까지 503(1102)로 끊긴 사례 있음.
- 실계정은 키워드가 수천 개라 한 요청 동기화는 불가 → 분할 동기화(Queues/Cron) 또는 Workers Paid($5, 요청당 CPU 최대 30초) 필요.
- D1 드라이버는 커뮤니티 제작. 트랜잭션 롤백이 실제로 동작하지 않을 수 있음(문장 단위 자동 커밋).

## 알려진 제약 / 기술 부채
- 프론트엔드: 링크 미리 불러오기 끔(정적 내보내기의 세그먼트 prefetch 경로가 404). 표 가상 스크롤 없음 → 수천 행이면 느려질 수 있음.
- 확장소재 화면은 조회 전용(수정은 공식 API 검증 전).
- 스키마: 로컬은 `create_all`, D1은 수동 SQL 마이그레이션. 모델 변경 시 `migrations/000N_*.sql` 추가 필요.
- 비밀번호 해시 PBKDF2 반복 100,000회(Workers WebCrypto 상한). OWASP 권장(600,000)보다 낮음.
- 실계정 네이버 API 클라이언트는 동기 `httpx` 사용 → Workers에서는 동작하지 않음. 실계정 연동 시 `fetch` 기반으로 교체 필요.
- 대량 작업은 요청 안에서 동기 실행 → 수백 행 이상이면 Celery 큐 필요.
- 네이버 호출 제한(rate limit) 대응·재시도 없음.
- 직원 추가는 가입된 이메일만 가능(초대 메일 없음).
- 실계정 쓰기는 `NAVER_ALLOW_REAL_WRITE=1` 전까지 차단.
