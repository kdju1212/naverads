# 구현 계획 — MVP v1.0 (SMB 전문 광고대행사)

> 최종 갱신: 2026-10-18. 진행 상태는 `docs/IMPLEMENTATION_STATUS.md`.

## 원칙
1. 대행사의 **다계정 통합 관리·대량 작업 효율**이 최우선. P2(직접 광고주) 기능은 MVP 일정에 넣지 않는다.
2. 하나의 광고 관리 엔진(백엔드 API) + `workspaces.type`으로 화면 분기.
3. Mock 모드 기본. 네이버 공식 API는 엔드포인트·필드별로 공식 문서 검증 후 실계정 쓰기를 연다.
4. 모든 쓰기 = 대량 작업 엔진(미리보기 → 실행 → 결과 → 감사 로그) 단일 경로.

## 기술 스택
- 백엔드: FastAPI + SQLAlchemy 2 + Pydantic (`backend/`) — **Cloudflare Python Workers(무료 플랜)** 에 배포
- 프론트엔드: Next.js 16 정적 내보내기 + TypeScript + Tailwind (`frontend/`) — Cloudflare Workers 정적 자산(`naverads`). 표는 자체 컴포넌트(정렬·검색·다중 선택), shadcn/ui·TanStack Table은 미사용
- DB: **Cloudflare D1**(운영, 커뮤니티 드라이버 `sqlalchemy-cloudflare-d1`) / SQLite(개발·테스트). 스키마는 `backend/migrations/*.sql`
- 비동기: Redis + Celery — 대량 작업 행 수가 커지면 도입. 1단계는 동기 실행
- 엑셀: openpyxl. 테스트: pytest, Playwright(2단계)

### 2단계 — 프론트엔드 P0 (1차 완료, 2026-10-18)
- 로그인, 계정 다중 선택기, 대시보드, 캠페인/광고그룹/키워드/소재 통합 테이블
- 대량 작업 미리보기·결과 화면, 엑셀 업로드, 작업 이력, 설정(계정 연결·직원·배정)

### 3단계 — 네이버 API 실계정 검증 (P0 잔여)
- 공식 문서로 엔드포인트·필드·호출 제한 재검증, 실계정 읽기 → 쓰기 순으로 오픈
- 파워링크 키워드 **대량 등록**(생성), 파워링크 소재 등록·교체 흐름, 쇼핑 상품소재 등록
- 확장소재 조회·ON/OFF, 성과 리포트(`/stats`, `/stat-reports`) 연동
- Celery 큐, 호출 제한 대응(재시도·백오프), Alembic 마이그레이션

### 4단계 — P1 차별화
- 계정 간 캠페인/광고그룹/키워드/소재 복사: 원본 조회 → 대상 계정 호환성 검증(비즈채널, 랜딩 URL, 상품 식별자) → 미리보기 → 신규 생성
- 광고주별 통합 성과 비교 화면, 담당자별 배정 현황
- 감사 로그 기반 되돌리기(역방향 대량 작업)

### 5단계 — P2 (MVP 출시 후, DIRECT_ADVERTISER)
초보자 화면, 성과 해석, 가이드, 오류 알림, 생성 마법사, 개선 제안.
