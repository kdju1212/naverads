# PRD — 네이버 광고 통합 관리 SaaS MVP v1.0

> 기준 문서: `Naver_Ads_SaaS_PROJECT_CONTEXT.md`. 충돌 시 마스터 컨텍스트가 우선한다.
> 최종 갱신: 2026-10-18

## 1. 제품 정의
**SMB 전문 광고대행사용 네이버 광고 통합 관리 SaaS.**
여러 광고주의 네이버 파워링크(`WEB_SITE`)와 쇼핑검색광고 쇼핑몰 상품형(`SHOPPING_PRODUCT_AD`)을 한 화면에서 조회·대량 수정한다.

- 형태: 웹 기반 구독형 SaaS
- 제외: Google Ads, 메타, 카카오, 네이버 GFA, 쇼핑검색 브랜드형·카탈로그형
- 가격 가설: 광고 계정당 월 19,900원, 무료 체험 제공(기간 미확정), 대행사 다계정 할인은 추후 검토

**핵심 가치:** 기능 수가 아니라, 대행사가 여러 광고주 계정을 *더 적은 시간과 실수로* 관리하게 하는 것.

## 2. 타겟 고객
| 구분 | 대상 | 시기 | 핵심 문제 |
|---|---|---|---|
| 1차 `AGENCY` | SMB 전문 광고대행사 (AE, 퍼포먼스 마케터, 운영 담당자, 팀장) | **MVP v1.0** | 계정 간 반복 이동·반복 작업, 대량 작업 실수, 광고주별 성과 비교 번거로움, 담당자별 작업 내역 추적 어려움 |
| 2차 `DIRECT_ADVERTISER` | 대행사 없이 직접 운영하는 SMB (스마트스토어, 자사몰, 소규모 브랜드) | MVP 출시·초기 고객 확보 후 | 운영 지식 부족, 설정 복잡, 성과 해석·입찰/예산 관리 어려움 |

**원칙:** 2차 타겟용 기능 때문에 MVP v1.0 일정을 지연시키지 않는다. 대신 DB·권한 구조는 처음부터 두 유형을 수용한다(`workspaces.type`).

## 3. 기능 범위 — 8개 모듈 유지
1. 계정 관리 2. 캠페인 관리 3. 광고그룹 관리 4. 키워드 관리(파워링크 전용) 5. 소재·상품소재 관리 6. 확장소재 관리 7. 엑셀 대량 관리 8. 성과 조회·분석

파워링크와 쇼핑검색은 API·데이터 구조가 다르다.
- 파워링크: 캠페인 → 광고그룹 → **키워드** + 텍스트 소재(`TEXT_45`) + 확장소재
- 쇼핑검색 상품형: 캠페인 → 광고그룹 → **상품소재**(`SHOPPING_PRODUCT_AD`, 소재 단위 입찰가). 키워드 등록 UI·파워링크 전용 확장소재를 적용하지 않는다.

### P1 — 대행사 차별화
1. 계정 간 캠페인 복사 2. 계정 간 광고그룹 복사 3. 계정 간 키워드·소재 복사
4. 여러 계정 동시 선택 후 대량 작업 5. 광고주별 통합 성과 비교 6. 담당자별 광고 계정 배정
7. 실패한 대량 작업만 재실행 8. 변경 전후 비교 및 가능한 설정 복구

**계정 간 복사 원칙:** 공식 API에 "복사" 기능이 있다고 가정하지 않는다. 원본 조회 → 대상 계정 권한·비즈채널·랜딩 URL·상품 식별자 호환성 검증 → 미리보기 → 승인 후 대상 계정에 **신규 생성**. 쇼핑 상품소재는 대상 계정에 동일 상품이 없거나 비즈채널이 다르면 복사 불가로 표시한다.
**복구 원칙:** 감사 로그의 변경 전 값으로 *역방향 대량 작업*을 생성해 미리보기 후 실행한다(ON/OFF·예산·입찰가 등 수정 가능한 필드만). 삭제된 객체 복구는 지원하지 않는다.

### P2 — 직접 광고주 확장 (MVP 이후)
초보자용 화면, 성과 자동 해석, 입찰가·예산 가이드, 설정 오류 알림, 광고 생성 마법사, 성과 개선 제안.

## 5. 권한 모델
- 대행사(workspace) 1 : N 직원(membership), 1 : N 광고 계정(workspace_ad_accounts)
- 역할: `OWNER`, `ADMIN` — 연결된 전 계정 조회·수정, 직원·계정 연결 관리 / `MEMBER` — **배정된 계정만**, 계정별 `VIEW` 또는 `EDIT`
- 모든 조회·쓰기·대량 작업은 서버에서 계정 단위로 개별 검증. 대량 작업은 생성 시와 실행 시 두 번 검증.
- 광고 계정 연결 시 해당 API 자격증명으로 실제 조회가 되는지 확인한 뒤 연결한다. 해제 시 데이터·이력은 보존하고 접근만 차단한다.

## 6. 안전 원칙
- 모든 쓰기 작업은 **미리보기 → 승인(실행) → 결과** 순서. 즉시 실행 API 없음.
- 미리보기는 광고주(계정)별로 변경 전/후 값과 유효성 오류를 보여준다.
- 성공/실패/부분 실패를 행 단위로 기록하고, 실패 행만 재실행 가능.
- 모든 성공 변경은 사용자·계정·객체·전후 값과 함께 감사 로그에 남긴다.
- Mock 모드가 기본. 실계정 쓰기는 공식 API 검증 전까지 서버 플래그(`NAVER_ALLOW_REAL_WRITE`)로 차단.
- API 비밀키는 암호화 저장, 응답으로 반환하지 않는다.

## 7. 구독·결제
구독 데이터(`plans`, `subscriptions`)는 광고 관리 테이블과 분리한다. 광고 관리 기능은 구독 테이블을 참조하지 않는다. 실제 결제 연동은 정책 확정 전까지 구현하지 않는다.

## 8. 성공 지표 (검증 가설)
- SMB 전문 대행사 5~10곳 체험에서 반복 작업(다계정 ON/OFF·입찰가 수정) 소요 시간 단축 확인
- 대량 작업 실패율·오입력 건수 감소
