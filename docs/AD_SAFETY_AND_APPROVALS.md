# 광고비 안전장치·변경 승인 유지보수 노트

작성: 2026-11-01 · 브랜치 `feat/ad-safety` · 마이그레이션 `0015_account_safety.sql` · 자료 확인일: 2026-11-01

## 1. 안전장치

조직·광고 계정마다 두 가지 금액을 저장한다. 표는 `account_safety`이고, 같은 고객번호를 다른 조직이 연결하면 그 조직은 따로 정한다.
- **하루예산 관리 기준**: 켜진 캠페인들의 하루예산 설정액 합계가 넘으면 안 되는 금액.
- **클릭당 최대 입찰가**: 키워드·광고그룹·쇼핑 소재·플레이스 그룹 입찰가와 자동입찰 최대 입찰가의 상한.

설정·변경:
- 관리자(OWNER·ADMIN)만 할 수 있다: `PUT /workspaces/{ws}/ad-accounts/{id}/safety`.
- 화면에서 네이버의 지금 현황을 보고 "확인했어요"를 체크해야 저장된다(`confirmed=true`). 서버가 정하는 기본 금액은 없다.
- 바꿀 때마다 `audit_logs`에 `SAFETY_SET`과 이전·이후 값을 남긴다. 누가 언제 정했는지는 `set_by`·`set_at`에 있다.

처음 연결:
- 계정을 연결하고 동기화한 뒤 설정 화면이 그 계정의 안전장치 패널을 연다.
- 패널은 켜진 캠페인별 하루예산 설정액과 합계, 계산 불가 이유, 필요한 조치를 보여 준다(`GET .../safety`).
- 설정하지 않은 계정은 대시보드 상단에 경고가 뜬다.

### 합계 계산 (`safety.Snapshot.total`)
- 네이버의 지금 설정을 그 자리에서 읽는다: `GET /ncc/campaigns`, 필요하면 `GET /ncc/adgroups?nccCampaignId=`.
- 켜진(`userLock=false`) 캠페인만 센다.
  - 캠페인에 하루예산(`useDailyBudget`·`dailyBudget`)이 있으면 그 값만 더한다. 그 아래 광고그룹 예산은 캠페인 예산 안에서 쓰이므로 더하지 않는다.
  - 캠페인에 하루예산이 없으면 켜진 광고그룹 하루예산의 합을 더한다. 이때 켜진 그룹 하나라도 예산이 없으면(무제한) 계산할 수 없다.
- 공유예산: 캠페인이나 그룹에 `sharedBudgetId`가 있으면 계산할 수 없다. 공식 이슈(#962)로 확인한 것은 공유예산이 캠페인용과 광고그룹용(ownerType)으로 있고 `sharedDailyBudget`을 갖는다는 것까지다. 개별 예산과 어떻게 합쳐지는지는 확인하지 못해 막는다.
- 하루예산 없는 켜진 캠페인이 10개를 넘으면 계산할 수 없다. 무료 플랜은 요청 1번에 외부 호출 50번까지라서다.
- 상품 유형(파워링크·쇼핑·플레이스·그 밖)을 구분하지 않고 같은 규칙을 쓴다. 브랜드검색처럼 하루예산이 없는 계약형 캠페인이 켜져 있으면 무제한으로 보여 계산할 수 없다(막힘). 이 동작은 실계정 확인이 필요하다.
- 계산할 수 없거나 네이버 조회에 실패하면 광고 시작·증액은 막고 이유를 알려 준다. 조회와 끄기는 된다.

### 검사 규칙 (`safety.check`)
| 작업 | 검사 |
|---|---|
| 켜기(캠페인·광고그룹·키워드·소재·확장소재 ON), ADVoost 켜기 | 설정돼 있음 + 변경 후 합계 계산 가능 + 합계 ≤ 관리 기준 |
| 캠페인 하루예산 올리기 | 같음(지금 값보다 크거나 같으면 증액으로 본다). 무제한 → 금액 설정은 줄이기 |
| 입찰가 변경, 입찰가가 있는 키워드·광고그룹 생성, 쇼핑 소재 입찰가 | 설정돼 있음 + 입찰가 ≤ 클릭당 최대 입찰가 |
| 끄기, 예산 줄이기, 삭제, 제외검색어, 조회 | 검사 없음(항상 가능) |
| 캠페인 생성 | 꺼진 상태로 만들어지므로 켤 때 검사 |

- 합계가 이미 기준을 넘는 계정은 끄거나 줄이기 전까지 켜기·증액이 모두 막힌다. 합계가 그대로인 키워드 켜기도 막힌다.
- 미설정 계정은 비용이 늘 수 있는 모든 작업이 막힌다(0015 이후 기존 계정 포함).

### 적용 위치(우회 경로 없음)
- `bulk.safety_blocks`가 `execute_job` 안에서 실행 직전에 행을 막는다. 웹 대량 작업, Claude `execute_job`, 예약 실행(크론), 자동입찰, 목표 ROAS가 모두 이곳을 지난다.
  - 입찰가 상한은 행마다, 합계는 계정마다(그 계정의 켜기·증액 행을 모두 반영한 뒤) 검사한다.
  - 막힌 행은 FAILED와 이유로 남고, 나머지 행은 실행된다(일부 성공 = PARTIAL).
- 미리보기(`create_job`): 최대 입찰가를 넘는 행은 바로 INVALID가 된다. 응답의 `safety`에 계정별 변경 후 합계와 막힐 이유가 들어간다. 웹 작업 상세와 Claude `preview_changes`가 이를 보여 준다.
- 예약 등록(`schedule_bulk_job`): 예약 시점에도 검사해 걸리면 예약하지 않는다. 실행 시점에 다시 검사하고 조건이 달라졌으면 실행하지 않는다(행 FAILED, 작업 결과·대시보드 실패 작업에 표시).
- 플레이스(`place._guard`): plan과 apply 모두 검사한다. apply는 네이버를 다시 읽는다.
- 쇼핑 상품소재(`shopping_ads`): 입찰가 상한.
- 자동입찰 규칙 저장(`main.set_auto_bids`)과 실행(`bulk.run_auto_bids`): 아래 3절.

### 하루예산 설정액은 실제 과금 상한이 아니다
- 화면과 Claude에는 "하루예산 설정액"이라고만 쓰고, 절대 상한이라고 표현하지 않는다. 모든 승인·미리보기에 `safety.OVERSPEND_NOTE`를 붙인다.
- 근거: 네이버는 하루예산을 넘을 것으로 예상되면 광고를 '중지'로 바꾸지만, 검색 결과에서 실제로 빠지기 전에 생긴 클릭은 과금될 수 있다.
  - 공식 원문 링크는 확인하지 못했다. 네이버 광고 도움말 '하루예산' 항목에서 원문을 확인해 이 줄을 바꿀 것.
  - 2차 출처(2026-11-01 확인): https://inside.ampm.co.kr/insight/3941 (대행사 블로그, "중지되었다고 해도 일정시간 노출되어 초과 과금 발생 가능")

## 2. 변경 승인 (사용자 결정 2026-11-01: A — Claude 안에서 승인)

- 조회·분석은 승인 없이 쓴다.
- 비용·노출에 영향을 주는 변경은 서버에 저장된 변경 요청을 실행하는 방식이다.
  - **대량 작업**: 미리보기(`bulk_jobs`·`bulk_job_rows`)가 승인할 변경 요청이다. 실행은 저장된 행 그대로만 한다(요청 본문으로 내용을 바꿀 수 없음).
    - 행마다 `VALID→RUNNING` UPDATE 한 문장으로 동시 실행을 한 번만 처리한다.
    - 실행 직전에 권한·안전장치·네이버 지금 값을 다시 확인한다. 예약 작업은 미리보기 값과 지금 값이 다르면 실패한다.
    - 감사 로그: `JOB_PREVIEW`(대기), 행별 UPDATE·CREATE·DELETE, `JOB_DONE`·`JOB_PARTIAL`·`JOB_FAILED`.
  - **플레이스**: `approval_requests`에 계획을 저장한다(사람·조직·계정·정확한 변경 내용 해시·15분 만료).
    - 같은 사람·같은 내용·한 번만 실행할 수 있다. 실행 직전에 다시 검사한다.
    - 감사 로그: `APPROVAL_PENDING`·`APPROVAL_SUCCESS`·`APPROVAL_PARTIAL`·`APPROVAL_FAILED`·`APPROVAL_EXPIRED`·`APPROVAL_REJECTED`.
    - 승인 카드에는 승인 / 수정하기 / 취소가 있다. 수정과 취소는 거절로 기록하고, 수정은 만들기 단계로 돌아간다.
- Claude에서는 미리보기나 계획 결과를 채팅에 표로 보여 준 뒤 실행 도구를 부르고, 허용 버튼이 승인이다(14-11·사용자 결정 A).
  - 웹에 별도 승인 대기 화면은 만들지 않았다.
  - 한계: 요청한 사람과 승인한 사람이 같다. Claude에서 "항상 허용"으로 두면 묻지 않고 실행된다. 다만 서버의 안전장치는 그대로 적용된다.
- **긴급 중지**: `POST /workspaces/{ws}/stop`, Claude 도구 `stop_ad`. 승인·안전장치 없이 바로 OFF로 바꾸고 `EMERGENCY_STOP`을 기록한다. 수정 권한은 필요하다. 플레이스 화면의 "바로 끄기"가 이걸 쓴다.

## 3. 자동입찰 허용 범위

- 규칙 저장이 곧 범위 승인이다. 범위는 대상 광고 계정·키워드, 기기·목표 순위, 최대 입찰가(계정 클릭당 최대 입찰가 이하), 실행 기간(`ends_on`, 오늘~90일)이다.
  - 응답 `scope`와 웹 확인창이 변경 방식을 보여 준다: 10분마다 +20%/-10%, 키워드당 하루 24번.
- 대상 추가·기간 연장·최대 입찰가 상향은 다시 저장해야 한다(재승인, 감사 로그 `AUTO_BID_SET`).
- 실행할 때마다 확인한다:
  - 규칙을 만든 사람의 지금 수정 권한
  - 기간(`ends_on`이 없거나 지났으면 실행 안 함)
  - 계정 안전장치(미설정이면 실행 안 함)
  - 입찰가 = min(규칙 최대, 계정 최대)
  - 그 뒤 `execute_job`의 안전장치를 한 번 더 거친다.
- 중지는 언제든 할 수 있다: `enabled=false`(기간 없어도 됨) 또는 해제(삭제).
- 0015 이전 규칙은 `ends_on`이 NULL이라 다시 승인할 때까지 실행되지 않는다(화면에 "기간 승인 필요").

## 5. 마이그레이션·기존 계정 전환

1. `cd backend && npx wrangler d1 migrations apply naverads --remote`로 0015를 적용한 뒤 push(배포)한다. 순서가 바뀌면 자동입찰 목록 조회가 없는 열 때문에 실패한다.
2. 배포 직후 모든 기존 계정은 미설정이다. 광고 켜기·예산 증액·입찰가 변경·자동입찰이 막히고, 끄기·조회는 된다.
3. 관리자가 설정 > 광고 계정 > "안전장치 정하기"에서 현황을 보고 금액을 정한다.
4. 기존 자동입찰 규칙은 자동입찰 화면에서 기간을 정해 다시 승인한다.

## 8. 실계정 확인이 필요하거나 남은 제한

1. 실계정 응답의 `useDailyBudget`·`sharedBudgetId` 모양과, 브랜드검색 등 다른 캠페인 유형의 예산 필드. 지금은 없으면 무제한으로 보고 막는다.
2. 캠페인 하루예산과 광고그룹 하루예산이 둘 다 있을 때 네이버가 어떻게 적용하는지. 지금은 캠페인 값만 센다.
3. 공유예산은 계산하지 않고 막는다. 정확한 합산 규칙을 확인하면 `Snapshot.total`을 고친다.
4. 광고그룹 하루예산 변경 기능은 없다(대량 작업 미지원). 생기면 `ops_of_row`에 증액 검사를 추가해야 한다.
5. 승인은 A 방식이다(요청자 = 승인자, Claude 허용 버튼). 다른 사람의 결재는 없다.
6. 예약 작업이 실행 시점에 막히면 작업 결과·대시보드에만 표시된다. 메일 같은 별도 알림은 없다.
7. 운영 D1에서 안전장치 조회·저장을 직접 해 보지 않았다. 로컬 D1에는 0015 적용까지만 확인했다.
