## 2. 쓰기 전에 사장님께 의미와 광고비 영향을 꼭 설명할 작업

조사 결과 기준(네이버 API 사실):

| 작업 | 설명할 내용 |
|---|---|
| 캠페인·광고그룹·키워드·소재 켜기 | 켜는 순간부터 노출·클릭 과금 가능 |
| 캠페인·광고그룹·공유예산 하루예산 올리기 | 하루 지출이 늘 수 있음. 하루예산은 절대 상한이 아님(3장) |
| 입찰가 올리기(키워드·그룹·쇼핑 상품소재) | 클릭당 비용이 오름 |
| 매체·타기팅 입찰 가중치 올리기(#17 networkBidWeight, #48) | 화면에 보이는 입찰가보다 실제 입찰가가 커짐 |
| 타기팅 변경(#49) | 본문에 없는 코드는 전부 꺼짐 → 의도치 않게 노출이 줄거나 바뀜 |
| 확장검색 켜기(useExpSearch) | 등록하지 않은 검색어에도 노출 → 클릭·비용 증가 가능 |
| ADVoost Max(aiAdsOptIn) | 파워링크 그룹에서 **값을 안 주면 켜짐**(2026-07-15) |
| ADVoost 플레이스(useAdvoost) | 켜면 입찰가·매체·타기팅을 못 바꿈, 지출은 하루예산으로만 조절 |
| 쇼핑 전환목표 자동입찰 | 하루예산 안에서 네이버가 입찰가·소재 노출을 직접 관리 |

| 공유예산 만들기·빼기·삭제 | 캠페인·그룹의 예산 기준이 바뀜 |
| WEBSITE_INFO 확장소재 등록 | API 등록 = 사이트 정보 수집·활용 동의로 간주, 정보 책임은 광고주 |

## 3. 광고비 관련 확인된 사실과 설계 주의

**공식 자료로 확인된 사실**
- 캠페인 `dailyBudget`: "캠페인에 설정된 하루 예산 최대값", `useDailyBudget`이 true일 때만 적용, 설정 안 하면 0 저장 [명세 Campaign].
- 소진 방식: 빠른 소진(ACCELERATED, 기본) / 균등 소진(STANDARD) [명세].
- `budgetLock`: "노출 잠김 여부"(예산 때문에 노출이 멈췄는지) [명세 Adgroup·SharedBudget·Bizmoney].
- 성과 데이터는 약 2시간 늦고 최대 48시간 안에 무효 클릭 제거 등으로 바뀔 수 있다 [공지 2025-09-26].
- 2026-03-30부터 보고서 비용은 VAT 포함 정수 [공지 2026-02-11].
- 쇼핑 자동입찰은 "하루예산 내에서" 관리한다고 안내 [2025-10-15].

**공식 자료에 없는 것(미확인)**
- 하루예산을 넘는 과금이 생기는지, 얼마나 넘을 수 있는지.
- 캠페인 하루예산 + 광고그룹 하루예산 + 공유예산이 동시에 있을 때 어느 것이 먼저 적용되는지.
- ADVoost(Max·플레이스)의 실제 과금 방식과 하루예산 초과 여부.

**서비스 설계상 주의(우리 판단)**
- 하루예산을 "이 이상 절대 안 나간다"고 안내하지 않는다. 네이버가 광고를 멈추기까지 지연이 있을 수 있다고 보고 설계한다(서비스 안내 문구·약관과 같은 입장).
- 성과·비용 숫자는 "잠정"으로 보여 주고, 실시간 지출 차단 근거로 쓰지 않는다.

## 6. 공식 명세만으로 확정하기 어려워 추가 확인이 필요한 작업

1. ADVoost 플레이스 `fields=useAdvoost` — 명세 JSON에 없음(릴리스 노트만). 이 서비스 구현도 실계정 미확인.
2. 쇼핑 상품소재 등록 형식(`isList=true` 배열)·상품 식별자(`referenceKey`)·입찰가 변경(`fields=adAttr`) — 명세에 없음.
3. 확장소재 내용 수정 가능 여부(fields 없는 전체 변경).
4. 제외검색어 조회에서 `type=EXP_SEARCH` 사용 가능 여부.
5. 쇼핑 자동입찰 `autobidStrategy`에서 노트의 "고정값" 외 값(MAX_CLICK, TARGET_CPA 등) 허용 여부.
6. 타기팅을 바꾸는 세 경로(광고그룹 fields / criterion / targets)의 권장 경로와 서로의 관계.
7. 플레이스 확장소재(PLACE·PLACE_SMART_ORDER·PLACE_BEAUTY_STYLE), PLACE_ADGROUP_TAG의 내용 형식.
8. 하루예산 초과 과금, 캠페인·그룹·공유예산 동시 적용 규칙, ADVoost 과금 방식.
9. 확장소재 글자 수 제한(명세에 없음).
10. 서명에 쿼리 문자열을 넣는지(공식 예시는 경로만).
11. 권한 등급별로 허용되는 API 작업 목록.
12. `systemBiddingType=ML`의 의미.
