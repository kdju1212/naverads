# 네이버 검색광고 API 조사 (전체 개요·목차)

- **조사일**: 2026-11-08
- **조사 방법**: 공식 문서 저장소를 직접 내려받아 명세 JSON을 기계적으로 세고, 릴리스 노트·공지를 읽었다. 네이버 API는 한 번도 호출하지 않았다(읽기 전용 자료만).
- **목적**: 마케팅을 잘 모르는 소상공인이 Claude와 대화하며 네이버 검색광고를 관리하는 이 서비스에서, API로 무엇을 할 수 있고 무엇이 광고비에 영향을 주는지 정리.

## 엔드포인트 집계 기준과 총개수

- **기준**: 공식 문서 사이트가 읽는 명세 JSON 9개의 `paths`에 있는 **(경로 표기, HTTP 메서드) 한 쌍 = 1개**. 같은 경로라도 메서드가 다르면 따로 센다.
- **총 127개** (조사일 기준). 명세에 `deprecated: true`로 표시된 작업은 0개.

## 확인하지 못한 항목 (요약)

명세와 노트가 다르거나 공식 자료에 없어 **미확인**으로 둔 것. 자세한 내용은 [04 1장](04-features.md#1-명세-json과-릴리스-노트가-다른-곳)과 [05 6장](05-service-usage.md#6-공식-명세만으로-확정하기-어려워-추가-확인이-필요한-작업).

1. 하루예산 초과 과금 여부·정도, 캠페인·광고그룹·공유예산 동시 적용 규칙, ADVoost 과금 방식
2. ADVoost 플레이스 `useAdvoost` — 릴리스 노트에만 있음
3. 쇼핑 상품소재 등록 형식·상품 식별자·입찰가 변경 방식 — 명세에 없음
4. 확장소재 내용 수정 가능 여부, 확장소재 글자 수 제한
5. 플레이스 확장소재·플레이스 그룹 태그 형식, PLACE 비즈채널을 API로 등록할 수 있는지
6. 권한 등급별 허용 작업, 서명에 쿼리 문자열 포함 여부, 엔드포인트별 호출 한도 숫자
7. 응답 예시 — 명세 JSON 대부분에 응답 예시가 없다. 03의 요청 본문 예시는 명세 필드로 만든 가상값이고, 응답 예시는 명세 example이 있는 모델만 실었다(나머지는 "공식 자료에서 확인되지 않음")

## 다시 만들기

명세가 바뀌면 03·06을 다시 만든다.

```bash
git clone --depth 1 --branch gh-pages https://github.com/naver/searchad-apidoc.git /tmp/searchad-gh-pages
python docs/naver-searchad-api/tools/gen.py docs/naver-searchad-api /tmp/searchad-gh-pages
```

- 새 엔드포인트가 생기면 스크립트가 `missing names`로 알려 준다 → `tools/names.tsv`에 작업명·쉬운 설명·구분·영향을 한 줄 추가하고 다시 실행.
- 01·04·05와 이 README는 사람이 쓴 문서라 함께 고친다(엔드포인트 번호가 바뀌면 01의 `#번호` 링크도).
- 릴리스 노트는 `gh-pages`의 `_posts/`에서 조사일 이후 파일만 읽으면 된다.
